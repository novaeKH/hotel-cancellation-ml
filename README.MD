# Hotel cancellation

Учебный проект с полным циклом разработки модели для оценки риска отмены бронирования — от анализа данных до API и production monitoring.

## Задача

Отель передаёт менеджерам бронирования с высоким риском отмены для дополнительного подтверждения. Чтобы сотрудники не тратили время на большое количество ложных тревог, модель должна выполнять условие `Precision >= 0.70`. Среди подходящих порогов выбирается вариант с максимальным `Recall`.

## Что реализовано

- исследование и очистка данных, удаление признаков с утечкой target;
- feature engineering и разделение данных по времени;
- сравнение моделей и подбор параметров LightGBM и CatBoost;
- запуск LightGBM v1 и проверка качества на новых данных;
- анализ data drift, переход на CatBoost с native categorical features;
- отдельный production monitoring на периоде, который не использовался при обучении;
- FastAPI для получения прогноза и Docker для воспроизводимого запуска.

Вся последовательность анализа и обучения находится в `notebooks` и выполняется по порядку от `01` до `10`.

## Проблемы и решения

**Случайный split давал бы слишком оптимистичную оценку.** Бронирования разделены по времени: модель всегда обучается на прошлом и проверяется на будущем.

**После запуска LightGBM качество снизилось.** На данных февраля–апреля изменились доля отмен и распределения важных признаков. Модель не подгонялась под этот период: сначала был проведён анализ drift, затем начат новый цикл обучения.

**В данных много категориальных признаков с высокой кардинальностью.** Вместо One-Hot Encoding для новой версии использован CatBoost, который работает с категориями напрямую.

**Нужно было честно проверить CatBoost v2.** Модель обучена только на истории до апреля, апрель оставлен для предвыкладочной проверки, а май–август использованы исключительно для monitoring. На production-периоде бизнес-условие снова не удержалось, поэтому результат сохранён без подбора нового порога по будущим данным.

## Запуск API в Docker

```bash
docker build -t hotel-cancellation .
docker run --rm -p 8000:8000 hotel-cancellation
```

После запуска Swagger доступен по адресу `http://127.0.0.1:8000/docs`, проверка состояния модели — `http://127.0.0.1:8000/health`.

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
